= Ammitto US OFAC SDN data

image:https://github.com/ammitto/data-us/actions/workflows/fetch.yml/badge.svg["Fetch Data", link="https://github.com/ammitto/data-us/actions/workflows/fetch.yml"]

This repository stores the Specially Designated Nationals and Blocked
Persons List (SDN List) as YAML for Ammitto. The US Treasury's Office of
Foreign Assets Control (OFAC) publishes the official list; Ammitto generates
one file per listed individual, entity, vessel or aircraft in `processed/`.

== Source

* Publisher: Office of Foreign Assets Control (OFAC), US Department of the Treasury
* List page: https://ofac.treasury.gov/specially-designated-nationals-and-blocked-persons-list-sdn-human-readable-lists
* File downloaded (XML): https://www.treasury.gov/ofac/downloads/sdn.xml

OFAC lists individuals and companies owned or controlled by, or acting for or
on behalf of, targeted countries, and individuals, groups and entities, such as
terrorists and narcotics traffickers, designated under programs that are not
country specific. Their assets are blocked.

== Contents

`processed/` holds one file per SDN entry, named after its OFAC UID:
`processed/10001.yaml` is UID 10001.

`processed/_index.yaml` lists every file, with the time of the last fetch.

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `uid` | string | OFAC UID of the entry
| `sdn_type` | string | `Individual`, `Entity`, `Vessel` or `Aircraft`
| `last_name` | string | Family name, or the whole name for entities, vessels and aircraft
| `first_name` | string | Individuals: given names
| `title` | string | Title or position, where given
| `program_list.programs` | list | Sanctions program codes, such as `SDNT`
| `aka_list.items` | list | Other names: `last_name`, `first_name`, `type` and `category`
| `address_list.items` | list | `address1` to `address3`, `city`, `state_or_province`, `postal_code`, `country`
| `id_list.items` | list | Identifiers: `id_type`, `id_number`, `id_country`, `issue_date`, `expiration_date`
| `date_of_birth_list.items` | list | `date_of_birth` and `main_entry`
| `place_of_birth_list.items` | list | `place_of_birth` and `main_entry`
| `remarks` | string | Remarks published with the entry
|===

Items in these lists also carry their own OFAC `uid`.

`sources/` holds a hand-curated sample entry and supporting reference data,
with their schemas in `schemas/`; the daily fetch does not update it.
`downloaded/us-govt-data.xml` is an empty file and `update.log` an older log;
the daily fetch updates neither. `processed/` is the list.

== Using the data

Clone or download this repository and run either example from its root
directory. The Python example requires PyYAML
(`python3 -m pip install PyYAML`).

Ruby:

[source,ruby]
----
require "yaml"

Dir.glob("processed/[0-9]*.yaml").sort.each do |path|
  record = YAML.safe_load_file(path)
  name = [record["first_name"], record["last_name"]].compact.join(" ")
  programs = record["program_list"]["programs"].join(",")
  puts [record["uid"], record["sdn_type"], programs, name].join("\t")
end
----

Python:

[source,python]
----
import glob
import yaml

for path in sorted(glob.glob("processed/[0-9]*.yaml")):
    with open(path, encoding="utf-8") as f:
        record = yaml.safe_load(f)
    name = " ".join(p for p in (record.get("first_name"), record["last_name"]) if p)
    programs = ",".join(record["program_list"]["programs"])
    print(record["uid"], record["sdn_type"], programs, name, sep="\t")
----

The same list, harmonized with the other sources into JSON-LD:
https://www.ammitto.org/api/v1/sources/us.jsonld

== Harmonized field mapping

The https://github.com/ammitto/ammitto/blob/main/lib/ammitto/sources/us/transformer.rb[us transformer]
maps the processed source fields below to canonical Ruby attributes.
Entity classes are in `Ammitto::Ontology::Entities`, entry/regime classes in
`Ammitto::Ontology::Sanction`, and nested values in
`Ammitto::Ontology::ValueObjects`. JSON-LD serialization can use different keys.

[cols="2,2,4",options="header"]
|===
| Source fields | Canonical target | Transformation

| `uid`, `sdn_type`, `entity_type`
| `Entity.id`, concrete entity class; `SanctionEntry.reference_number`
| Use the UID for source-scoped IDs. Explicit entity type takes precedence over SDN type when selecting person, organization, vessel or aircraft.

| `first_name`, `last_name`, `aka_list`
| `Entity.names` (`NameVariant`)
| Build the primary name from the name parts and add non-primary aliases with detected scripts.

| `address_list`, `id_list`
| `PersonEntity.addresses`, `identifications`; `OrganizationEntity.addresses`
| Join address lines into street text. For persons, normalize identification types and retain document number/country and notes.

| `date_of_birth_list`, `place_of_birth_list`
| `PersonEntity.birth_info` (`BirthInfo`)
| Pair dates with places by position; preserve parsed date/year/range precision and circa markers. Place-only records are retained when no dates exist.

| `nationality_list`, `citizenship_list`
| `PersonEntity.nationalities`
| Combine and deduplicate countries; retain the separate source lists in entry source metadata.

| `id_list`, `vessel_info`
| `VesselEntity.imo_number`, `flag_state`, `vessel_type`, `call_sign`
| Read the IMO identification; prefer the stated vessel flag and fall back to an address country.

| `vessel_info.gross_registered_tonnage`, `vessel_info.vessel_owner`
| `VesselEntity.tonnage.grt` (`Tonnage`), `owner_link` (`EntityLink`)
| Accept digit-only gross registered tonnage; preserve other stated tonnage text in source metadata. Link an owner name with `relationship_type` set to `owned_by`.

| `id_list`, `address_list`
| `AircraftEntity.registration`, `registration_country`
| Use a registration identification and the first stated address country for the aircraft flag.

| `program_list`, `remarks`, `title`
| `SanctionEntry.regime`, `remarks`, `raw_source_detail.source_specific_fields`
| The first programme selects the regime; retain all programmes and additional source fields under `us:` metadata keys.

|===

== Updates

The `Fetch Data` workflow (`.github/workflows/fetch.yml`) downloads the list
every day at 06:45 UTC and commits any change to `processed/`. It runs with
`--prune`, so an entry OFAC has removed is deleted here on the next fetch.

== Maintaining the data

The link:.github/workflows/fetch.yml[fetch workflow] uses Ruby 3.3 and Bundler.
To refresh `processed/` locally, install the link:Gemfile[Gemfile] dependencies
and run the same command from the repository root:

[source,shell]
----
bundle install
bundle exec ammitto fetch us --format yaml --output-dir processed --verbose --prune
----

This regenerates `processed/` and removes entries absent from the fetched
list. Fetching and parsing are implemented in the
https://github.com/ammitto/ammitto[Ammitto gem].

For edits to the curated samples and reference data in `sources/`, run
`bundle exec rake validate`. The link:Rakefile[Rakefile] checks only those
source files against `schemas/`.
